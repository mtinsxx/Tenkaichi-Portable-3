# PSP-native PSMT8 multi-source index cache (experimental)
Base: PR #9 `TP3-NATIVE-T8-INDEX-REUSE-20261028`.
Build ID: `TP3-PSP-T8-4WAY-20261028`.

## What changed
The previous cache reserved one static 256 KiB buffer for **one** 512x512 linear PSMT8 source. When a battle alternated stage textures, each distinct source displaced the previous one, even if each texture was only 128x128 and needed 16 KiB.

This version divides the SAME 256 KiB budget into **four independently keyed 64 KiB slots**. A source smaller than or equal to 256x256 can coexist with three other stage textures. The cache stores the native linear PSMT8 *indices*, not the CLUT; each palette continues to be loaded from live GS memory. Original TBP, TBW, full source dimensions and a combined original-GS-page **content hash** guard reuse. A change in any source page invalidates the cache entry automatically. Collisions in lookup compare the whole identifying key, not just a hash bucket.

On a miss, the original decoder runs and samples the output against the PS2 scalar GS reader before storing. An empty slot is chosen first; after all four are used, the least recently accessed slot is overwritten only after the new image has been decoded. Textures exceeding 64 KiB remain fully decoded by the existing path, but are not retained in this four-way cache; they are never truncated or partially used as an old image.

This is CPU-side index caching, **not** the GPU's texture allocator and not PS2 local memory emulation. The GPU continues using the normal PSP GUI texture cache and the original primitive order.

## Safety & limitations
- No additional static memory consumption beyond the previous 256 KiB buffer.
- Both PSP workflows include host tests for four simultaneous 128x128 images, LRU selection, validity of source-only page hashes, changes to TBP/TBW/sizes, oversize bypass and defensive input checks.
- The old direct GS texture+CLUT cache remains the first-level cache.
- 512x512 textures no longer participate in the secondary index cache (trade-off for keeping four smaller textures resident); such textures still render through the unchanged GS decoder.
- The game does NOT yet use native converted mesh or animation inputs. Full stage399 native compilation, GPU→GS framebuffer coherence and exact PS2 depth/alpha feedback remain unfinished.
- A successful GitHub Actions build is not proof of PPSSPP correctness or FPS gain. Run the same arena, record log and watch for the earlier invalid-memory crash.
